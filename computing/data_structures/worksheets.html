Data Structures · Teacher notesdata-structures.html

Teacher notes

Investigation 1: A stack is LIFO

What to look for: 5 then 7: last in, first out. TopOfStack goes 0, 1, 2, then back to 1 and 0. Popping does not need to erase the value, only move the pointer.

Investigation 2: Overflow and underflow

What to look for: Pushing onto a full stack is an overflow error; popping an empty stack is underflow. An array-based stack has a fixed size, so the code must check TopOfStack before each operation.

Investigation 3: A circular queue

What to look for: Rear wraps round to 0: Rear ← (Rear + 1) MOD 8. Without wrapping, a linear queue would report 'full' even with empty slots at the front.

Investigation 4: Linked list: insertion moves pointers, not data

What to look for: They take nodes 0, 1, 2 from the free list in that order, but the pointers are set so the list reads 10 → 20 → 30. Nothing moves in the array.

Investigation 5: Deleting from a linked list

What to look for: The previous node's pointer skips over it, and the node is put back at the head of the free list, so it is reused by the next insertion.

Investigation 6: Building a binary search tree A level

What to look for: A perfectly balanced tree of height 3. In-order (left, root, right) visits 20, 30, 40, 50, 60, 70, 80: sorted order.

Investigation 7: A bad insertion order A level

What to look for: Every item goes right: the tree is a long chain (a linked list). Finding 60 takes 6 comparisons, O(n) not O(log n). Random insertion order usually gives a bushy tree.

Investigation 8: Pre-order and post-order A level

What to look for: Pre-order (root first): 50, 30, 20, 40, 70. Post-order (root last): 20, 40, 30, 70, 50. Post-order is used to delete a tree; pre-order to copy it.

Batch experiment 1: Searching a linked list

A linked list can only be followed from the start, even if it is sorted: no binary search, so O(n).
Theory ((n + 1)/2): 5: 3 · 10: 5.5 · 20: 10.5 · 40: 20.5 · 80: 40.5
Result from a test run: 5: 3.07 ± 0.0265 · 10: 5.53 ± 0.144 · 20: 10.2 ± 0.266 · 40: 21.1 ± 0.413 · 80: 40.5 ± 0.902 (mean ± SE, 4 runs each)

Batch experiment 2: Binary search tree: average search (A level)

About 1.39 log₂ n: random trees are bushy, only about 39% worse than a perfectly balanced tree (log₂ n).
Theory (2(1 + 1/n)Hₙ − 3): 7: 2.93 · 15: 4.08 · 31: 5.31 · 63: 6.61 · 127: 7.94 · 255: 9.29
Result from a test run: 7: 3.2 ± 0.215 · 15: 4 ± 0.0558 · 31: 5.37 ± 0.188 · 63: 6.48 ± 0.122 · 127: 7.83 ± 0.244 · 255: 9.31 ± 0.325 (mean ± SE, 5 runs each)

Batch experiment 3: Sorted input ruins a tree (A level)

Each new item goes to the right of the last: a chain of height n, so searching is O(n). Self-balancing trees (AVL, red-black) fix this; they are beyond 9618.
Theory (n (a chain)): 5: 5 · 10: 10 · 20: 20 · 40: 40 · 80: 80
Result from a test run: 5: 5 ± 0 · 10: 10 ± 0 · 20: 20 ± 0 · 40: 40 ± 0 · 80: 80 ± 0 (mean ± SE, 1 runs each)

Batch experiment 4: Height of a random tree (A level)

Usually 10 to 12: taller than perfectly balanced, but far below the 63 of a chain.
Theory (balanced: log₂ 64 = 6): 6
Result from a test run: mean 11.5, SD 1.39, SE 0.0802 from 300 runs

Batch experiment 5: In-order traversal sorts

Every time: everything in a node's left subtree is smaller and everything in its right subtree larger. Inserting then traversing is a sort (a 'tree sort').
Theory (always): 1
Result from a test run: mean 1, SD 0, SE 0 from 200 runs
