Teacher notes

Investigation 1: One fetch–execute cycle

What to look for: MAR ← [PC]; PC ← [PC] + 1 and MDR ← [[MAR]] (address and data buses); CIR ← [MDR]; decode; then for LDD: MAR ← address, MDR ← [[MAR]] (buses again), ACC ← [MDR]. Each memory read uses the address bus, data bus and control bus.

Investigation 2: Why does the PC go up by 1 straight away?

What to look for: During the fetch, before the instruction is executed, so it already points to the next instruction. A jump simply overwrites it. Without incrementing, the CPU would run the same instruction for ever.

Investigation 3: A loop

What to look for: CMP #0 compares ACC with 0 and sets a flag in the status register. JPN LOOP puts LOOP's address into the PC if the flag is NOT set (ACC ≠ 0), so the instructions repeat. Output: 54321.

Investigation 4: Addressing modes

What to look for: Immediate: 60 itself. Direct: the contents of address 60 (62). Indirect: address 60 holds 62, and address 62 holds 99. Indexed: address 60 + 1 = 61, which holds 5.

Investigation 5: Summing an array

What to look for: LDX LIST reads address LIST + IX. Each time round, INC IX moves to the next item. The total is 30 (7 + 3 + 12 + 8).

Investigation 6: Bit manipulation

What to look for: AND with 00001111 is a mask: it keeps the low four bits and clears the rest. LSL #1 doubles the value but the top bit falls off the end of the 8-bit register. LSR #2 divides by 4 (dropping remainders).

Investigation 7: Pipelining A level

What to look for: Without pipelining 100 × 5 = 500. With it, a new instruction finishes every cycle once the pipe is full: 5 + 99 = 104. Each taken branch flushes the instructions already fetched, wasting 4 cycles.

Batch experiment 1: Cycles to sum an array

A straight line: a fixed set-up cost plus the same number of micro-steps for every item (the loop body). The gradient is the cost of one pass round the loop: O(n).
Result from a test run: 1: 77 ± 0 · 2: 132 ± 0 · 4: 242 ± 0 · 8: 462 ± 0 · 12: 682 ± 0 · 16: 902 ± 0 (mean ± SE, 1 runs each)

Batch experiment 2: Memory reads and writes per instruction

Every instruction needs at least one memory access (its fetch); loads and stores need another. That shared memory traffic is the Von Neumann bottleneck.
Theory (1 (the fetch alone)): 1: 1 · 2: 1 · 3: 1 · 4: 1 · 5: 1
Result from a test run: 1: 1.6 ± 0 · 2: 1.27 ± 0 · 3: 1.52 ± 0 · 4: 1.67 ± 0 · 5: 1.14 ± 0 (mean ± SE, 1 runs each)

Batch experiment 3: Pipelining and branches (A level)

Branches are why pipelined processors try to predict which way a branch will go. Without a pipeline the 100 instructions would take 500 cycles whatever p is.
Theory ((5 + 99) + 100p × 4): 0: 104 · 0.05: 124 · 0.1: 144 · 0.15: 164 · 0.2: 184 · 0.3: 224 · 0.4: 264
Result from a test run: 0: 104 ± 0 · 0.05: 124 ± 3.33 · 0.1: 145 ± 4.39 · 0.15: 169 ± 6.57 · 0.2: 183 ± 4 · 0.3: 226 ± 6.46 · 0.4: 263 ± 8.68 (mean ± SE, 8 runs each)

Batch experiment 4: Pipeline speed-up (A level)

Almost k times faster for long runs of instructions, as long as every stage takes the same time and nothing stalls.
Theory (nk/(k + n − 1)): 1: 1 · 2: 1.98 · 3: 2.94 · 4: 3.88 · 5: 4.81 · 6: 5.71 · 8: 7.48 · 10: 9.17
Result from a test run: 1: 1 ± 0 · 2: 1.98 ± 0 · 3: 2.94 ± 0 · 4: 3.88 ± 0 · 5: 4.81 ± 0 · 6: 5.71 ± 0 · 8: 7.48 ± 0 · 10: 9.17 ± 0 (mean ± SE, 1 runs each)
