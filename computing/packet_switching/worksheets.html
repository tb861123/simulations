Packet Switching Lab · Teacher notespacket-switching.html

Teacher notes

Investigation 1: Different routes, different order

What to look for: Adaptive routing recalculates the tables every 5 ms from the queue lengths, so later packets are sent round a busy route and some overtake earlier ones (dots below the rising trend on the arrival graph). B holds the later packets in its buffer and uses the sequence number in each header to put them back in order.

Investigation 2: Same route, same order

What to look for: With static routing every router's table stays the same, so all the packets follow the same route and arrive in order. Packets CAN take different routes, but with stable tables they often take the same one. The analytic check also passes: the finish time matches the store-and-forward calculation exactly.

Investigation 3: When a link fails (packet switching)

What to look for: Packets on the failed link are lost. For 10 ms the routers still send packets towards it, and those are lost too. Then the tables are recalculated and packets go round. A's timers run out for the lost packets and it re-sends them. The transfer still completes: packet switching routes round failures.

Investigation 4: When a link fails (circuit switching)

What to look for: The reserved circuit is broken, so the call is dropped and the blocks in transit are lost. A must set up a whole new circuit (setup again), then send the rest of the data. A dedicated circuit cannot route round a failure.

Investigation 5: A real-time call

What to look for: With packet switching each frame meets different queues, so the delay varies (jitter) and some frames are late; late frames are useless, so they are not re-sent. The circuit gives a constant delay and no jitter, which suits a call, but the reserved link is idle most of the time: the call needs only 64 kbit/s, so the utilisation is a few per cent.

Investigation 6: Setup time against overheads

What to look for: A circuit spends about 32 ms setting up before any data moves, but then sends with no headers and no store-and-forward. For a small message the setup dominates, so packet switching finishes first; only for a very big message (here above about 170 kB) does the circuit win. Try the batch run "Packet or circuit: which finishes first?".

Investigation 7: A busy network

What to look for: Queues build where routes share links. A packet arriving at a full buffer is thrown away (tail drop). A gets no acknowledgement for it, its timer runs out, and it re-sends the packet. The transfer still completes, but takes longer. Bigger buffers drop fewer packets but packets wait longer in them.

Investigation 8: The best packet size A level

What to look for: Each packet carries 44 B of header and trailer, so small packets waste more of the link (and 16 small packets carry little data per round trip of the sliding window). But every router must receive a whole packet before sending it on (store-and-forward), so a large packet adds a long wait at each hop. The finish time is T = Σ(L/Rᵢ + dᵢ) + (N − 1)·L/R_slowest; the analytic check confirms it. (With small packets, 16 of them at once overflow a small buffer at R1, so this uses 512-packet buffers.)

Investigation 9: Why packets have a hop limit A level

What to look for: R9's faulty entry sends packets for B back to R6, which sends them to R9 again. Each router takes 1 off the hop limit, and at 0 the packet is thrown away. Without a limit, looping packets would circulate for ever, filling queues and crowding out other traffic. A larger limit lets them bounce longer before dying.

Batch experiment 1: Packet or circuit: which finishes first?

The circuit's setup (about 32 ms) is paid once; the packets' cost (44 bytes of header and trailer on every packet, plus store-and-forward at each router) grows with the message. So packet switching wins for small messages and the circuit wins only for big ones: on this network the line crosses zero at about 170 kB. Both runs are exact (no randomness on a quiet network), so repeats agree.

Batch experiment 3: Other traffic and out-of-order arrival

Even with no other traffic, about half the packets arrive out of order: adaptive routing counts the message's own queue, so it spreads one message over several routes. Other traffic changes which packets overtake which (the spread between runs), but hardly changes how many. With static routing the answer would be 0 on a quiet network.
Result from a test run: 0: 6 ± 0 · 20: 8.4 ± 0.678 · 40: 8.8 ± 0.8 · 60: 8 ± 0.316 · 80: 8.8 ± 0.374 · 100: 8.2 ± 0.97 (mean ± SE, 5 runs each)

Batch experiment 4: Small buffers and re-sending

Small buffers overflow, so packets are dropped and must be re-sent. Big buffers drop almost nothing, but packets can wait a long time in them (in real networks too-big buffers cause "bufferbloat").
Result from a test run: 2: 53.5 ± 3.8 · 4: 7.25 ± 0.629 · 6: 1.5 ± 0.289 · 8: 1.5 ± 0.645 · 12: 0.25 ± 0.25 · 16: 0.5 ± 0.5 · 24: 0.75 ± 0.479 · 32: 0.75 ± 0.479 (mean ± SE, 4 runs each)

Batch experiment 5: Jitter on a call

On a quiet network every frame meets empty queues, so the jitter is almost zero; busy queues make it grow. That is why circuits (or quality-of-service priority) suit real-time calls.
