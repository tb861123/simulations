    What the specification asks (9618 §14.2)

    • Circuit switching and packet switching: what each is, their benefits and drawbacks, and where each is applicable.
    • The function of a router in packet switching.
    • How packet switching passes messages across a network, including the internet.

    Key points this simulation demonstrates

    Packet switching: the message is split into packets. Each packet's header holds the source and destination addresses and a sequence number. Each router reads the destination address, looks it up in its routing table and forwards the packet to the next router (hop). Packets are routed independently, so they may take different routes and arrive out of order. The destination uses the sequence numbers to reassemble them. Missing packets are detected and sent again. Links are shared, so there is no setup delay and failed links can be routed around. Shared links also mean queueing, variable delay (jitter), possible loss and per-packet header overhead.

    Circuit switching: a dedicated path is set up between sender and receiver before any data is sent. All data follows that path and arrives in order with a constant delay. The full bandwidth of the circuit is reserved, even when idle, so nobody else can use it. If a link on the path fails the connection is lost and must be set up again. The circuit is released at the end. It suits real-time communication such as calls.

    Be careful — common over-simplifications:
    • "Every packet takes a different route" — packets can take different routes. With stable routing tables they often take the same one. Compare adaptive and static routing.
    • "Circuit switching is always faster" — it has no store-and-forward or header overhead, but it has a setup delay. For short messages packet switching can finish first (try 4 above).
    • "Routers change the packet's addresses" — the source and destination IP addresses stay the same end to end. What changes at each hop is the link-layer frame (MAC addresses). This matters in §14.1.
    Beyond the specification (not required for 9618 §14.2): store-and-forward timing, queueing theory, adaptive link-state routing, RTT estimation, and hop limits. Dijkstra's algorithm itself is in §18.1. The four-layer TCP/IP model is in §14.1.

    The network

    11 routers and two hosts (A and B), joined by full-duplex links. Each direction of a link has its own output queue in the sending router. Core links run at the bandwidth you choose. The links between each host and its router run at 10 Mbps. Propagation delays are proportional to the drawn length (about 1.5–2.5 ms per core link) and are illustrative. Addresses use reserved documentation ranges.

    Timing (store-and-forward)

    A router must receive a whole packet before forwarding it. On each link a packet experiences:

    • serialisation delay L / R: time to put L bits onto a link of rate R;
    • propagation delay d: time for the signal to travel along the link;
    • queueing delay: time waiting behind other packets. If a router's buffer is full, the packet is dropped.

    Packets needed: N = ⌈message bytes ÷ (packet bytes − 44)⌉. Each packet has a 40-byte header (IPv4 + TCP for files, or IPv4 + UDP + RTP for calls) and a 4-byte trailer (an error check that strictly belongs to the link-layer frame).

    Routing extension

    Each router builds its table with Dijkstra's algorithm (link-state routing). Static routing uses a fixed distance-based metric. Adaptive routing adds each output's current queueing delay and refreshes tables every 5 ms, so a busy route is avoided. After a link fails or is restored, routers take 10 ms to learn about it. Real internet routing (e.g. OSPF inside an organisation, BGP between networks) normally reacts much more slowly to load than this. Adaptive mode deliberately exaggerates route variation so it can be seen.

    Reliability extension

    For files, B acknowledges every packet. If A's timer for a packet expires, A sends it again. The timer adapts to measured round-trip times (as TCP does, RFC 6298) and doubles after each timeout. A gives up after 8 retransmissions. Simplification: real TCP uses a sliding window and congestion control and does not release the whole message at once. A call stream is never retransmitted, because late audio is useless.

    Circuit switching

    A setup request travels hop by hop (4 ms processing per switch), reserving each link. A confirmation returns (1 ms per hop). Data then flows as a continuous bit stream at the circuit rate: no headers, no queues, no store-and-forward. Transfer time is setup + bits ÷ Rc + Σd. Reserved links carry nothing else. A link failure drops the call and A redials after 10 ms. Simplification: real telephone circuits reserve a fixed slice of a link (e.g. 64 kbit/s), not the whole link. Most modern telephony is itself carried over packet networks.

    What it leaves out

    Bit errors and corrupted packets, router processing time, DNS, ARP, NAT, fragmentation, congestion control, quality-of-service priority, and the internal detail of MAC addressing. Other users' traffic is random, not based on measured internet data.

    How the results are checked

    • Conservation: every packet created is delivered, dropped or still in the network, at every instant.
    • Analytic check: with static routing, no other traffic and no failures, the simulated finish time is compared with an independent store-and-forward calculation. The circuit finish time is compared with setup + bits ÷ Rc + Σd.
