Teacher notes

Investigation 1: Place values

What to look for: 77 = 01001101 (64 + 8 + 4 + 1). −77 = 10110011: flip every bit of 77 (10110010) and add 1. In two's complement the top bit is worth −128: −128 + 32 + 16 + 2 + 1 = −77.

Investigation 2: Hexadecimal

What to look for: 1101 = D, 0110 = 6, so D6 (= 214). Each hex digit is exactly 4 bits, so hex is a short, error-resistant way to write binary (colours, memory addresses, MAC addresses).

Investigation 3: Adding and carrying

What to look for: 105 + 55 = 160 = 10100000. As unsigned numbers that is fine. But in two's complement 10100000 = −96: two positives gave a negative, so the OVERFLOW flag is set (160 > 127).

Investigation 4: Subtracting by adding

What to look for: 00110010 + 11101100 = 1 00011110: ignore the carry out; the 8-bit answer 00011110 = 30 is correct, and there is no overflow (the signs were different).

Investigation 5: Characters

What to look for: 65 = 'A'. Adding 32 gives 97 = 'a': upper and lower case letters differ in a single bit, so case conversion is one OR or AND with a mask.

Investigation 6: Reading a floating-point number A level

What to look for: Mantissa 0.1011 = 0.5 + 0.125 + 0.0625 = 0.6875; exponent 3; value 0.6875 × 2³ = 5.5. It is normalised: it starts 0.1.

Investigation 7: 0.1 cannot be stored exactly A level

What to look for: 0.1 = 0.0001100110011… in binary, a recurring fraction, so it must be rounded: stored as about 0.1001 or 0.0996. Errors build up over many additions. The same happens (much more finely) with 64-bit doubles: 0.1 + 0.2 ≠ 0.3.

Investigation 8: Range against precision A level

What to look for: 6 + 6: largest about 0.97 × 2³¹ (≈ 2 × 10⁹), but only 5 bits of precision. 8 + 4: largest 0.99 × 2⁷ = 127, but 7 bits of precision. More exponent bits = range; more mantissa bits = precision.

Batch experiment 1: How often does 8-bit addition overflow?

A quarter of all pairs overflow: half the pairs have the same sign, and half of those add to more than 127 or less than −128. Programs must check the overflow flag.
Theory (exact count: 16 384/65 536 = ¼): 0.25
Result from a test run: mean 0.25, SD 0.0304, SE 0.00175 from 300 runs

Batch experiment 2: Precision and mantissa bits (A level)

Each extra mantissa bit halves the rounding error (a straight line with gradient −1 on this log₂ scale). 64-bit doubles have a 53-bit mantissa: errors around 10⁻¹⁶.
Theory (≈ log₂(0.35 × 2^−(m−1))): 4: -4.51 · 6: -6.51 · 8: -8.51 · 10: -10.5 · 12: -12.5 · 16: -16.5 · 20: -20.5
Result from a test run: 4: -4.46 ± 0.0248 · 6: -6.44 ± 0.0153 · 8: -8.51 ± 0.0206 · 10: -10.5 ± 0.0129 · 12: -12.5 ± 0.0205 · 16: -16.4 ± 0.0117 · 20: -20.5 ± 0.00983 (mean ± SE, 4 runs each)

Batch experiment 3: Range and exponent bits (A level)

Each extra exponent bit DOUBLES the power of 2 available: the range grows enormously (from about 2 to about 10³⁸), but the precision does not change.
Theory (≈ 2^(e−1) − 1): 2: 1 · 3: 3 · 4: 7 · 5: 15 · 6: 31 · 7: 63 · 8: 127
Result from a test run: 2: 0.989 ± 0 · 3: 2.99 ± 0 · 4: 6.99 ± 0 · 5: 15 ± 0 · 6: 31 ± 0 · 7: 63 ± 0 · 8: 127 ± 0 (mean ± SE, 1 runs each)

Batch experiment 4: Adding 0.1 again and again (A level)

Rounding errors pile up, and once the total is large each 0.1 is rounded more coarsely (the spacing of floats grows with their size). Never test floats for exact equality.
Theory (exact arithmetic): 1: 0 · 5: 0 · 10: 0 · 20: 0 · 40: 0 · 60: 0 · 80: 0 · 100: 0
Result from a test run: 1: -3.91e-4 ± 0 · 5: 0 ± 0 · 10: 0 ± 0 · 20: -0.0625 ± 0 · 40: -0.188 ± 0 · 60: 0.25 ± 0 · 80: 0.75 ± 0 · 100: 1.25 ± 0 (mean ± SE, 1 runs each)
